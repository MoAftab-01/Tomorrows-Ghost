## 2. API request/response contract

**Endpoint:** `POST http://127.0.0.1:8002/ghost/chat`

**Request body:**
```json
{
  "message": "What did I believe in 2016?",
  "conversation_id": "ghost-abc123"
}
```

**Request validation:**
- `message`: string, 1-280 chars.
- Empty message → `422` (Pydantic validation) or `400` (manual check).
- Oversized (>280) → `422`.

**Response (success — `200`):**
```json
{
  "answer": "... generated by gemma3:4b ...",
  "conversation_id": "ghost-abc123",
  "references": [
    {"source":"synthetic/fixture_memory_2016.md","excerpt":"...","status":"supported|partial|insufficient"}
  ],
  "evidence_summary": {"total":1,"supported":1,"partial":0,"sources":["synthetic/fixture_memory_2016.md"]},
  "model": "gemma3:4b",
  "synthetic_disclosure": "Synthetic simulation only...",
  "status": "generated"
}
```

**Response (error states):**
- `ollama_unreachable` (connection error)
- `ollama_timeout` (timeout after 90s)
- `ollama_unavailable` (HTTP non-200)
- `other` (unexpected exception — no raw stack trace exposed to frontend)

In all error cases, `answer` is an explainable message, `references` is preserved, and `synthetic_disclosure` clearly states synthetic simulation / absence of evidence.

## 3. Retrieval / evidence approach

- **Approach:** Small deterministic keyword-matching layer over `backend/data/synthetic/fixture_memory_2016.md`.
- **No FAISS/vector DB added** (only 1 fixture; vector retrieval over-engineered for this stage).
- **Evidence status logic:**
  - `supported` — query terms overlap with fixture keywords (`future`, `loneliness`, `clarity`, `belief`, etc.).
  - `partial` — fixture has relevant content but query asks for interpretation not directly stated.
  - `insufficient` — query asks about clearly unrelated topics (`favorite pet`, `favorite color`, etc.); retrieval returns `insufficient` so AI is instructed to acknowledge absence rather than invent.
- **Every reference points to a real source excerpt** from the existing synthetic fixture file.
- **No fabricated citations.** No confidence percentages.

## 4. Conversation behavior

**System prompt:**
- Roleplays fictional 2016 younger self (reflective, curious, emotionally resonant, slightly mysterious, natural).
- Boundaries enforced in prompt: never claims real past self, never claims actual consciousness/memories/supernatural knowledge, never invents historical events, never claims to know the user's future, never treats synthetic fixtures as real user uploads.
- Explicit distinction required in response: (1) what source says, (2) interpretation, (3) what cannot be known.

**Memory store:** In-memory `CONVERSATIONS` dict (ephemeral, single-user, bounded, no persistent DB). Documented as ephemeral/demo-only.

**No streaming:** `stream: false` in Ollama payload; no decorative streaming UI indicators.
